# Android build and validation matrix

The PowerShell entry point is `scripts/build-android-matrix.ps1`. It builds real
debug APKs, inspects their native contents and optionally installs/tests them.
It never commits, tags or publishes. Mathematical algorithms are unchanged.

## Artifact strategy

Per-ABI APKs are the default: they make native loading and failures attributable
and avoid shipping other CPUs' code. ARM64 is first. The installed r28c NDK
declares ARM64, ARMv7, x86_64 and x86 support; compilation and runtime eligibility
are assessed separately. `-Abis` selects a distinct subset. Normal direct Gradle
builds retain the prior ARM64/x86_64 defaults.

`-IncludeUniversal` performs a separate Gradle build containing the ABI set whose
individual builds passed; it requires at least two. It is a convenient sideload
option, not four renamed copies. An AAB is appropriate for store-side delivery,
but cannot be installed directly with ADB and adds no local API coverage. No AAB
is generated here. Debug remains the default; [build-release.ps1](releasing.md)
loads the permanent private signing identity and invokes the same matrix with
Release variants. Debug APKs are not renamed or promoted to release artifacts.

## Tools and configuration

Use JDK 17, Python 3.10+, the pinned Gradle 8.13/AGP 8.13.2, build tools 35.0.0,
SDK 36, NDK 28.2.13676358 and CMake 3.22.1 from [setup](setup.md).
The script respects an existing `local.properties` SDK pointer, then process SDK
variables, then the local SDK under `.dev/tools`. It does not rewrite user configuration. Local SDK pointers,
credentials and private notes never become APK inputs.

All builds keep minSdk 26, compileSdk 36, targetSdk 36 and versionCode 4.
Debug uses versionName `0.1.0-dev`; Release uses `0.1.0` and the base application ID.
`axiomaAbis` and `axiomaBuildId` are validated Gradle properties
used only to select native targets and isolated output locations.

## Inspection

`scripts/android-artifacts.py` uses Python's standard ZIP/ELF/hash tools and the
installed `aapt`, `apksigner`, `zipalign` and NDK `llvm-readelf`. It checks:

- Nonempty APK, exact ABI set, package/version/SDK metadata and debug APK signature.
- Release applications must be non-debuggable and match the expected permanent
  signing certificate. Instrumentation targets the selected application variant.
- Actual `lib/<abi>/libaxioma.so`, ELF magic/class/machine/load-segment alignment.
- Defined exports for parse, evaluate, evaluateExact and calculateMode, not just strings.
- Native DT_NEEDED dependencies resolve to packaged libraries or allowed Android system libraries.
- APK ZIP alignment for 16 KB; every 64-bit library must also have ELF alignment
  of at least 16 KB. These static checks do not establish a 16 KB runtime test.
- Every pinned renderer file is present with its expected SHA-256; Internet
  permission and private/unsafe archive paths are rejected.

The current C++ runtime is linked statically. A shared runtime is required only
if an actual DT_NEEDED entry requests it; an empty/dummy library cannot satisfy
ELF and defined JNI-export validation.

## Runtime evidence

`-TestConnectedDevices` authorizes installation on the selected ready ADB devices;
`-Serial` restricts selection without placing personal serials in reports.
`-EmulatorApis @(33,34,35,36)` additionally boots dedicated official AOSP x86_64
images sequentially. [Testing](testing.md) describes the full suite.

Each matrix cell identifies Android/API/ABI and separates compilation,
installation and functional status. The same APK is reused across Android
versions. Device-advertised ABIs, process bitness, actual API and page size are
recorded. A 64-bit device does not prove that its OS admits a 32-bit process.
No ARM result is inferred from an x86_64 emulator. Inspect native-bridge metadata
before interpreting a translated environment as physical-architecture evidence.

Missing environments are explicitly blocked/not executed. Build-only exit code
zero means verified artifacts were produced, not that the entire runtime matrix
passed. Critical build/content/signature/JNI/function failures return nonzero.
`-RequireCompleteMatrix` makes missing requested runtime coverage nonzero too.
Known preexisting mathematical defects remain separate from compatibility checks.

## Output and cleanup

Everything generated by the build/validation workflow is under `artifacts/android/`:

```text
<abi>/Axioma-<abi>.apk
universal/Axioma-universal.apk       # only when requested and meaningful
tests/Axioma-instrumentation.apk    # only for requested runtime tests
manifests/build-manifest.json
reports/validation-report.md
reports/*.log
.build/                            # Gradle and inspection intermediates
```

The single central manifest contains tool/configuration metadata, each APK's
relative path, byte size, SHA-256, native libraries and static/runtime results,
the Android matrix, logs and owned-file hashes. It contains no credentials or
personal serials. The entire generated tree is ignored by Git.
Completed production bundles are frozen separately from disposable output
ownership. Their hashes survive in `release_bundle`/`preserved_releases`; later
debug builds preserve those files and reject changed preserved-release contents.

An exclusive lock prevents overlapping matrix runs. Repetition removes only
files identified by the previous generator manifest, after verifying all their
hashes and resolved containment; reparse/junction paths are rejected. Modified generated files are preserved by
refusing cleanup. No recursive deletion is used. Unknown files are not removed.
Gradle caches stay isolated under `.build/`; each final APK is moved to one
canonical path. Repeating the same command keeps the same final artifact layout;
byte-identical APKs are not promised across toolchains, debug keys or timestamps.
Native CMake/Ninja staging also uses `.build/<buildId>/native`, outside that
variant's Gradle `app` build directory, rather than the default `app/.cxx`.
SDK packages, Gradle's downloaded tool cache and dedicated AVD state remain local
development tools under `.dev/`; they are not distributable build artifacts.
Each ABI/universal/test invocation also has its own `--project-cache-dir` under
`.build/`; changing output roots must not share Gradle's task-output cleanup
history. The Gradle user cache/tool downloads can still be shared. A failed
`stripDebugDebugSymbols` output cleanup was recorded before this isolation;
it is a build-automation issue, not evidence of an unsupported ARMv7 instruction.
Only a recognized Gradle output-cleanup failure permits one bounded retry of
the entire build/lint/dependency verification. Both exit codes and the failed
attempt log are retained. Compiler, APK-inspection and functional failures are
not silently retried or converted to success.
The output ledger is checkpointed atomically during builds and runtime testing,
so a failed finalizer does not leave the preceding run's ownership hashes in use.
Emulator redirected streams are raw `.build/` intermediates; sanitized reports
are separate files and can be read even while redirect handles finish closing.

## Commands

```powershell
.\scripts\build-android-matrix.ps1
.\scripts\build-android-matrix.ps1 -Abis @('arm64-v8a') -TestConnectedDevices
.\scripts\setup-android.ps1 -EmulatorApis @(33,34,35,36)
.\scripts\build-android-matrix.ps1 -IncludeUniversal -TestConnectedDevices -EmulatorApis @(33,34,35,36)
```
